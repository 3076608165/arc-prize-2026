# 后续优化方向：根据剩余时间控制训练预算

优先研究 AGI-2 的动态 16/8 次增广选择：时间充足保留 16 次，仅在剩余队列按已观测服务时间预计无法跑完时降为 8 次，并记录每次决策的输入。候选不得读取测试答案或依赖特定题号。先做预算决策的日志回放，再在同等时间预算下做前瞻对照；回放本身不能预测新策略的正确率。

依据来自已完成的一小时公开对照：16 次在截止前覆盖 32 个输出，8 次覆盖 40 个；最终正确输出为 4/172 与 13/172，双方均有候选的 26 个输出各正确 4 个。这只是固定排序队列上的一组诊断。完整比赛的 augment8 v10 分数为 27.64，低于原基线此前的 28.47–30.14 观测范围；不能把公开一小时结果外推成隐藏集增益，也不能仅凭这一次分数断言机制一定有害。

动态选择需要控制两个风险：早期少量短任务会低估剩余耗时；减少增广可能改变解码难度与耗时。因此下一轮必须固定保守估计器、暖启动任务数、决策阈值及最短预算，按任务输出记录训练选择、真实训练/解码耗时、截止前候选覆盖及最终正确率。基线仍为全 16 次，保留全 8 次作为诊断参照，不按排行榜最高单次分数选择策略。

已检查另一条低成本路线：前 8 个视图一致时停止后续解码。使用比赛实际公开文件回放历史候选池，144 个有候选输出中只有 7 个符合预先固定的规则，省去 56/1723 个已保存视图（3.25%），正确输出保持 45 个，无得失。未达到预定的至少 10 个输出且省去至少 10% 视图门槛，不进入 GPU 实验。视图数也不等于 GPU 时间。

AGI-3 的后续原型是“按当前画面记忆动作效果”：无效点击只在相同上下文降低优先级，画面变化后重新允许尝试，同时保留每十次点击九次推进完整扫描。独立候选与对照已生成，11 项机制测试通过，尚无性能提升结论。先完成现有 coverage 离线配对实验，再为此原型单独冻结验证，不把共同底座修复混入机制收益。

本轮还纠正了数据版本：Kaggle 2026 公开评估为 120 题、172 个输出；本地 Git 数据为 167 个输出。新的分析通过 competition_data.py 读取实际比赛文件并记录哈希。旧的 167 输出说明属于旧数据口径，不能用来校验当前 Kaggle 输出。

结果文件：agi2-coverage-v1/comparison.json、agi2-decode-budget-v2/result.json。AGI-3 活跃协议是 agi3-coverage-v2-offline/protocol.json；旧 v1 因运行环境元数据被刷新而失败，不恢复旧协议。
